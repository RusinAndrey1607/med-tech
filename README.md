# MedTech — Backend Practice Project

Backend-приложение для управления клиниками, пациентами и записями на приём. Проект создан для практики разработки backend-систем на NestJS с акцентом на архитектуру, надёжность обработки запросов, кэширование и асинхронную обработку событий.

## Стек технологий

* **Node.js, TypeScript, NestJS** — серверное приложение и микросервисы.
* **PostgreSQL, Prisma ORM** — хранение данных и работа с базой данных.
* **Redis** — кэширование данных.
* **BullMQ** — фоновые задачи и обработка очередей.
* **Kafka** — обмен событиями между сервисами.
* **JWT** — аутентификация.
* **Docker, Docker Compose** — контейнеризация и запуск инфраструктуры.
* **Swagger / OpenAPI** — документация API.

## Архитектура

Проект включает основное API и отдельные сервисы для обработки событий.

* **API** — бизнес-логика клиник, пациентов и записей на приём.
* **Audit Service** — обработка событий аудита, поступающих через Kafka.
* **Notification Service** — обработка событий, связанных с уведомлениями.
* **PostgreSQL** — основное хранилище данных.
* **Redis** — кэширование.
* **Kafka** — обмен событиями между приложениями.

Для фоновой обработки также используется подход с очередями и Outbox. Это позволяет практиковать надёжную передачу событий и отделять асинхронные операции от основного HTTP-запроса.

## Реализованные механизмы

* REST API на NestJS.
* DTO и валидация входных данных.
* Работа с PostgreSQL через Prisma.
* Проверка повторного создания записи на приём для одного пациента на одно время.
* Кэширование запросов с использованием Redis.
* JWT-аутентификация.
* Фоновые задачи и очереди.
* Outbox-подход для обработки событий.
* Kafka для взаимодействия между сервисами.
* Контейнеризация приложений и инфраструктуры через Docker Compose.

## Запуск проекта

### Требования

* Docker Desktop с Docker Compose.
* Git.

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd med-tech
```

### 2. Настройка окружения

Создайте локальный файл `.env` на основе `.env.example` и задайте значения переменных окружения, включая секреты JWT.

Не добавляйте `.env` с реальными секретами в Git.

### 3. Запуск приложения

```bash
docker compose up -d --build
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Посмотреть логи:

```bash
docker compose logs -f api audit-service notification-service
```

### 4. Остановка

```bash
docker compose down
```

Команда сохраняет данные в Docker volumes. Для полного удаления сохранённых данных используйте `docker compose down -v` — это удалит данные баз и других сервисов, хранящиеся в соответствующих томах.

## Сервисы и порты

| Сервис     | Порт на хосте |
| ---------- | ------------: |
| Main API   |          3000 |
| PostgreSQL |          5432 |
| Redis      |          6379 |
| Kafka      |          9094 |

Внутри Docker Compose сервисы обращаются друг к другу по именам сервисов и внутренним портам.
